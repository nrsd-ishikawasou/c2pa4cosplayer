## S-01a 通常的启动（到显示界面为止。串行）
```mermaid
sequenceDiagram
  participant OS
  participant AC as app-client
  participant ST as core-store
  participant ID as core-identity
  participant RF as core-ref
  participant MK as core-mark
  participant UI as ui
  OS->>AC: 启动
  AC->>AC: CPU的确认（x86-64-v3。第11章 3.1）
  alt 不支持
    AC->>OS: dialog“不支持此PC的CPU”→ 结束
  end
  AC->>AC: tauri-plugin-single-instance（9.3）
  alt 第2次启动
    AC-->>AC: 把参数（照片・文件夹）交给第1个后结束（S-01c）
  end
  AC->>AC: 以--crash-handler把自身作为子进程启动 → core-common CrashReport::init（第1章 10.3）
  AC->>ST: Paths::ensure_layout（B-020）
  AC->>AC: core-common Logging::init_logging(log_dir)、Clock::init(state_dir)（存放处从Paths传入）
  AC->>ST: RunMarker::last_exit_was_clean（B-026）
  AC->>ST: RunMarker::start
  AC->>ST: Settings::get（B-025。语言、显示）
  AC->>RF: Consent::consent_state（B-223）
  AC->>RF: Consent::terms_changed_since（条款的变更 → 再同意）
  AC->>ST: Schema::version_of / migrate（B-024。第9章 4.4）
  alt 迁移失败
    AC->>AC: 状态 = 迁移失败（只读）
  end
  AC->>RF: Store::minimum_version（B-224）
  alt 版本低于
    AC->>AC: 状态 = 低于最低版本
  end
  AC->>ID: IdentityStore::current（B-080）
  alt 没有
    AC->>AC: 状态 = 首次之前（S-02）
  else 有
    AC->>ID: Keystore::status（B-090）
    alt Linux且无Secret Service
      AC->>UI: startup_prompt（口令的窗口。第10章 3.6）
      UI->>AC: unlock_keystore（B-281）
      AC->>ID: Keystore::unlock
    end
    AC->>ID: IdentityStore::expiry_status（B-087）
    alt Stop20
      AC->>AC: 状态 = 超过20年
    end
  end
  AC->>AC: 状态 = 通常 / 未同意
  AC->>UI: 界面（接收B-295 webview_info，get_startup_state B-280）
  Note over AC: 到此为止是“10秒”的范围（第1章 14.1）
```

## 遗漏（事后发现并修正）
- 启动的串行段中的“条款变更的确认”（第12章 4.3）不在app-client页面`Startup::run`的注记中 → 在app-client.md的`Startup`中加了`terms_changed_since`（与本文件的S-01a一致）。
- 放置与读取`state/update-pending`的时机只在app-client的数据设计中，启动的串行（第1章 7）中没有“在显示界面之前替换”的位置 → 因第9章 4.1的OS关机项中有“下次启动时、在显示界面之前”，在第1章 7启动顺序的开头加了“若有`state/update-pending`则用已验证的分发物替换（第9章 4.1）”。
- 后台队列最后的“期限的通知”（第7章 6.3中未启动期间的部分）不在第1章 7的后台顺序中 → 加在第1章 7后台顺序的末尾。
