## 2. 許可範囲

### 2.1 選択肢（O-04「許可範囲の選択肢」 の決定）

基本の範囲（1つを選ぶ）

|ID|名前|内容|
|---|---|---|
|P1|鑑賞のみ|購入者本人が個人として画像を見ること。複製は購入者本人の端末への保存に限る|
|P2|鑑賞と私的な印刷|P1 に加え、購入者本人が個人の鑑賞のために印刷すること|

追加の許可（任意に付ける）

|ID|名前|内容|
|---|---|---|
|A1|SNS での紹介|購入者が自分の SNS で、縮小した画像（長辺1080画素以下。初期値）を、権利者の名前と識別番号を示して紹介すること。有償の配布・販売は含まない|
|A2|個人的な加工|購入者本人が個人として楽しむための加工（切り抜き・色の調整等）。加工した画像の公開は含まない（A1 を選んだ場合は A1 の範囲で公開できる）|
|A3|AI の学習・推論の許可|AI の学習・推論・データマイニングへの利用を許す（既定は不可。cawg.training-mining の4つの項目に反映。第3章 3.1「記録する項目」）|

常に含む条件

- 商用の利用（広告、商品化、有償の配布・販売）は、別途、権利者の書面の許諾が必要。
- 他人への譲渡・共有・転載は不可（A1 の範囲を除く）。
- 権利（著作権・肖像権）は購入によって移転しない。
- 照合データ（C2PA署名・不可視透かし・識別番号）を消してはならない。
- SNS 用の画像の既定の許可範囲は「P1 相当：閲覧のみ、転載禁止」とする（第3章 8.2「系統の差」）。

### 2.2 非技術者向けの説明

- 各選択肢に一文の説明と、「できること／できないこと」の絵つきの例を付ける（第10章「画面とデザイン」で画面にする）。
- 判定の基準：利用者の試行で、説明を読んだ利用者の8割以上が、選んだ範囲で購入者が SNS に載せてよいかを正しく答えられること（第10章「画面とデザイン」）。

### 2.3 画像との紐付け

- 販売の出力（受け渡し用）の単位で許可範囲を1つ選び、そのフォルダーのすべての画像の作品データ（rights）とマニフェスト（jp.nrsd.rights、cawg.metadata の利用条件、cawg.training-mining）に記録する（第3章「署名処理」）。
- 登録（第6章「登録と証拠保全」）の際、転載画像の不可視透かしから読み出した識別番号で作品データを引き、選んでいた許可範囲と照らして「何に抵触しているか」を示す（D-9-2「販売時に選んだ許可範囲を、転載が何に抵触しているかを判断する基準とする」）。

### 2.4 販売後の変更

- 既に配った画像の許可範囲は変えない（配った画像のマニフェストと同封文書が証拠になるため）。
- 範囲を広げたい場合は、権利者が購入者に別途の許諾を出す（本システムの外）。本システムは許諾の文面の例を示さない。許諾の条件（対価、範囲、期間）は取引ごとに決まり、ひな形で表せないため（DD-5-1「許可範囲は基本の範囲と追加の許可で選ぶ」）。
- 範囲を狭めることはしない（購入者が既に得た許諾を一方的に取り消すことになるため）。

## 3. 同封文書

### 3.1 構成

|ファイル|中身|言語|
|---|---|---|
|`00_RIGHTS_README.txt`|共通部（3.2）|日・中・英を1ファイルに並べる|
|`00_RIGHTS_<国コード>.txt`|国別部（3.3）|その国の主な言語と英語|
|`00_RIGHTS.json`|機械が読める許可範囲（ODRL 2.2。3.6）|—|

- 形式は TXT（UTF-8、BOM なし、改行 CRLF）とする。どの OS でも開け、Cloud のプレビューで読める（D-9-5「すべての国を網羅した情報をリンク先として公開し、購入者に多い国籍の分に限りテキストの文面を同封する」 の「TXT」）。
- フォルダーの最上位に置き、画像より先に並ぶよう名前の先頭を `00_` にする。

### 3.2 共通部の骨子

- 設計計画書 9.2「同封文書」の5つの事項（①権利に関する条項（権利が移転しない旨を含む）、②許可範囲、③無断で授受しない旨の一文、④照合データが消され範囲の外で使われた場合に権利者がとる手段、⑤どの行為がどの責任を問われ得るか）と、各行の対応は次のとおり。

|順|項目|骨子|計画書 9.2 の事項|
|---|---|---|---|
|1|この画像の権利者|ハンドルネーム、告知先アカウント|①に付け加えたもの（権利者を示す）|
|2|他人に無断で授受しないこと（DD-5-3「無断の授受を禁じる一文を共通部に置く」）|「この画像を、権利者の許可なく他人に渡したり、共有・転載したりしないでください」|③|
|3|権利は移転しないこと|購入によって著作権・肖像権は購入者に移らない|①|
|4|許可範囲|選んだ P・A の説明|②|
|5|照合データについて|画像に C2PA署名と不可視透かしと識別番号が入っていること（番号の一覧は `00_RIGHTS.json`）、故意に消すことは国によっては法律に違反し得ること（国別部を参照）|④の前提|
|6|範囲外の利用をした場合に権利者がとり得る手段|削除の申立て、損害賠償の請求等（国別部を参照）|④|
|7|何をすると何に問われる可能性があるか|国別部を参照。全網羅は公開ページのリンク|⑤|
|8|問い合わせ先|権利者の告知先アカウント|付け加えたもの|
|9|許諾の性質|許諾は購入者本人への非独占のもので、他人に譲り渡せず、他人に再び許諾できない。期間は定めない（画像を持つ限り）。地域は限らない|①|
|10|範囲の外の利用をした時|許諾は範囲の中の利用に限られ、範囲の外の利用はそもそも許されていない。権利者は許諾を取り消すことがある|①|

- 表現は事実の記載とし、強い契約の文言にしない（設計計画書 9.2「同封文書」：売れなくなる懸念への配慮）。
- 9 の許諾の性質は、販売の場の規約が会員に与える許諾の性質（Patreon の規約：非独占、譲渡不可、再許諾不可、取消可能な、私的・非商用の閲覧のための限定的な許諾。法務調査 L-17「販売プラットフォームの規約」）と食い違わないように揃える。販売の場の規約より広い許諾を与える場合（A1、A2）は、権利者が選んだものとして明示する。

### 3.4 書き換えの検出

- DD-5-4「同封文書の SHA-256 をマニフェストに記録する」。アプリの「確かめる」画面（第10章 G-13「確かめる」）に画像と同封文書のフォルダーを入れると、各ファイルの SHA-256 をマニフェストの一覧と比べ、一致・不一致・一覧にないファイル・足りないファイルを示す。画像そのものの確かめは第3章 10.2「利用者による確認」による。

### 3.5 法的な位置付け（法務で扱う）

- 同封文書は、Patreon 等の販売の場の規約の上で「作成者の許可」の内容を示すもの（法務 L-17「販売プラットフォームの規約」）。独立の契約として成立するかは国により異なり、専門家の確認を要する（I-08「権利文書の文言」）。本システムは同封文書を「事実と許可の範囲の表示」として扱い、契約の成立を保証しない。

### 3.6 機械が読める許可範囲（ODRL）

- 形式：ODRL 2.2 の JSON-LD（文脈は `http://www.w3.org/ns/odrl.jsonld`）。方針の種類は Offer（権利者が申し出る条件。購入者は特定しない）とする。
- 対応：

|許可範囲|ODRL での表し方|
|---|---|
|P1 鑑賞のみ|許可：`display`、`reproduce`（制約：購入者本人の端末への保存に限る）|
|P2 鑑賞と私的な印刷|P1 に加え、許可：`print`（制約：私的な利用）|
|A1 SNS での紹介|許可：`distribute`（制約：長辺1080画素以下、有償でない）。義務：`attribute`（権利者の名前と識別番号を示す）|
|A2 個人的な加工|許可：`modify`（制約：私的な利用）|
|A3 AI の学習・推論の許可|許可：本システムの拡張の操作 `nrsd:aiTraining`、`nrsd:aiInference`、`nrsd:dataMining`|
|常に含む条件|禁止：本システムの拡張の操作 `nrsd:commercialUse`（商用）、`distribute`（A1 の範囲を除く）、照合データの除去（`nrsd:removeProvenance`）。A3 を選ばなければ AI の3つの操作を禁止|

- 本システムの拡張の操作の名前空間は NRSD のドメインの URI とし、公開ページに操作の定義を載せる。
- 対象（Asset）は識別番号の一覧、申し出る者（assigner）は権利者のハンドルネームと告知コードとする。
- 例（P1 と A1 を選んだ場合の骨子）：

```
{
  "@context": "http://www.w3.org/ns/odrl.jsonld",
  "@type": "Offer",
  "uid": "urn:nrsd:policy:{一括処理の番号}",
  "assigner": {"uid": "urn:nrsd:notice:{告知コード}", "name": "{ハンドルネーム}"},
  "target": ["urn:nrsd:id:{識別番号}", "..."],
  "permission": [
    {"action": "display"},
    {"action": "reproduce", "constraint": [{"leftOperand": "purpose", "operator": "eq", "rightOperand": "nrsd:personalDeviceStorage"}]},
    {"action": "distribute",
     "constraint": [{"leftOperand": "nrsd:longEdgePixels", "operator": "lteq", "rightOperand": 1080},
                    {"leftOperand": "payAmount", "operator": "eq", "rightOperand": 0}],
     "duty": [{"action": "attribute"}]}
  ],
  "prohibition": [
    {"action": "nrsd:commercialUse"}, {"action": "nrsd:removeProvenance"},
    {"action": "nrsd:aiTraining"}, {"action": "nrsd:aiInference"}, {"action": "nrsd:dataMining"}
  ]
}
```

- `purpose`、`payAmount` は ODRL の共通の語彙の左辺（制約の対象）である。`nrsd:` の名前は本システムの拡張であり、公開ページで定義する。［要確認］実装の前に、ODRL の検証の道具で形の正しさを確かめる。
- ODRL の標準の操作の定義：display は「一時の表示」、print は「有形で永続の表示」、reproduce は「複製」、distribute は「第三者への提供」、modify は「内容の変更（新しい対象は作らない）」、attribute は「利用の際の表示」（W3C の ODRL の共通の語彙）。

### 3.8 国と言語の符号

- 国は ISO 3166-1 の2文字の符号で表す（例：JP、CN、US）。国別部のファイル名は `00_RIGHTS_<国の符号>.txt`。
- 同じ撮影を価格の違う複数の許可範囲で売る場合（例：支援の段階ごと）は、書き出しを許可範囲ごとに分ける（書き出しの1回に許可範囲は1つ。2.3）。書き出しごとに識別番号が別になる。

## 4. 文言の管理

|項目|方式|
|---|---|
|作成|NRSD が日本語で骨子から条文を起こし、英・中に翻訳する（翻訳は NRSD が確認）|
|確認|各国の文言は、その国の法に通じた専門家の確認を経てから公開する（I-08「権利文書の文言」）。確認を経ていない国の国別部は作らず、全網羅のリンクのみで示す|
|版|参照情報の包みの版（1から始まる整数。第8章 3.4「参照情報の包み」）と、文言ごとの版（別の項目）を持つ|
|配布|参照情報の包み（第8章 3.4「参照情報の包み」）として公開リポジトリとミラーに置き、アプリが取得・検証する（第1章 DD-1-6「参照情報は NRSD が電子署名して公開リポジトリとミラーに置く」）|
|法改正への追従|NRSD が四半期ごとに確認し、改正があれば版を上げる（第1章 18.1「NRSD の関与点と体制」）|

## 5. 国

- 同封する国：購入者に多い国籍の分を、利用者が「権利文書の対象国」（第1章 10.8「言語と国」）で選ぶ（複数可。設計計画書 9.3「対象とする国」）。購入者に多い国籍は利用者自身が把握している（設計計画書 9.3「対象とする国」）。アプリは既定の国を置かず、購入者の情報を持たない（販売管理は範囲外）。国を選ばない場合は共通部と全網羅のリンクのみを同封する。
- 購入者の国は絞れない（I-07「購入者の国の把握」の結論）。販売の場の登録の情報や接続の元の国は、VPN を通されれば意味を失い、購入者の国籍を確定できない。画像は国を越えて渡る。このため本システムは購入者の国に依存しない作りとする：共通部はすべての言語で同封し、全網羅の情報は公開ページのリンクで示し、国別部は利用者が自分の判断で選ぶ（選ばなくてもよい）。
- 全網羅のリンク先：公開リポジトリの公開ページ `/rights/`（各国の法の要旨と出典の一覧。参照情報から生成）。
- 準拠する法の考え方（法務で扱う。O-03「準拠する法の考え方」）：設計計画書 9.5「準拠する法の考え方（参考）」 の2層（許可範囲は契約の問題、侵害は保護が要求される国の法の問題とする）を参考とし、同封文書に「許可範囲の解釈は販売者（権利者）の国の法による」旨を載せる案を置く。採否は専門家の確認による（I-06「国ごとの権利の違い」、I-08「権利文書の文言」）。確認までは同封文書に書かず、販売者の国の入力も設けない（O-03「準拠する法の考え方」は案を置いた段階）。

## 6. 告知の支援

### 6.1 文例の段

|段|用途|骨子（日本語）|
|---|---|---|
|短|X・Instagram・小紅書のプロフィール（100〜160文字）|「無断転載禁止。写真には C2PA署名・透かし・識別番号があります。NRSD-XXXXX-XXXXX-XXXXX-XXXXX」|
|中|プロフィールに余裕がある場合|短と「確認方法：<公開ページの URL>」と「CR の印は写真の来歴の記録（C2PA）の印であり、AI 生成の表示ではありません」|
|長|固定の投稿、Patreon の About|次の項目：権利の所在、無断の転載・照合データの除去が違法となり得ること、申立て・損害賠償の意思、識別番号（画像の記録に入り、ファイル名の後ろにも付けられる番号。設計計画書 D-7-7「識別番号は、クライアントアプリが発行し、C2PAマニフェストに自動で記録する。ファイル名の後ろに付けるかは、保存の際に利用者が選ぶ」）の意味と確認方法、C2PA の確認の印が AI 生成の表示ではなく写真の来歴の記録であることの説明、告知コード、確認の方法（公開ページの URL。入手は README を指す）。作品登録番号（公的な登記・登録の番号）は、利用者が持つ場合に任意で書ける文字列とする|

- 各段を日・中・英で用意する。アプリは利用者のハンドルネームと告知コードを入れて、写しやすい形で示す（コピーのボタン）。

### 6.2 権利性の照合との関係

- 告知コードは第2章 DD-2-3「権利性の手がかりは告知先アカウントに掲げる告知コードとする」・第1章 8.2「識別子の体系」 のもの（個人のルートの指紋）。画像の C2PA署名の署名者と告知先アカウントの結び付きを、誰でも照合できるようにする（第2章 4.1「告知先アカウントとの照合」）。
- 告知の掲示を消したり書き換えたりすると、照合の手がかりが失われる。アプリは告知コードの掲げ方と、掲げ続けることの意味を案内する（第10章 G-04「告知の掲示」）。本システムは掲示を確かめない（D-5-5「本システムは照合の手段を提供するが、照合を代行しない」）。

### 6.3 短の文の下書き（3言語）

- 日本語：「無断転載禁止。写真には C2PA署名・透かし・識別番号があります。{告知コード}」
- 英語："No reposting. My photos carry a C2PA signature, watermark and ID. {notice code}"
- 中国語（簡体字）：「禁止转载。照片含 C2PA 签名、水印及识别编号。{告知コード}」
- 文字数：告知コードは28文字であり、上の文は告知コードを含めて日本語62文字、中国語54文字、英語94文字で、いずれも100文字以内に収まる（X の160文字、Instagram の150文字、小紅書のおおむね100字の内。第2章 2.2「告知コードを掲げる場所の上限」）。
- 下書きであり、確認は 3.7 と同じ。

## 8. 本章で宣言する破れ

- 同封文書は授受の途中で外され得る（D-9-4「同封文書に、画像を他人に無断で授受してはならない旨の一文を入れる。その欠損は権利者の過失によるものではない」：その場合は権利者の過失ではない）。画像のマニフェストの利用条件は残るが、SNS に上がれば消える。

- 専門家の確認を経ていない国は、国別部を作れない（全網羅のリンクのみ）。
