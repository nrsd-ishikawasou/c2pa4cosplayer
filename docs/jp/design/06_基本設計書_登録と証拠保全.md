## 2. 登録

### 2.1 手順

|段|利用者|アプリ|
|---|---|---|
|1|「転載を登録」を押し、転載ページの URL を貼る|URL を正規化し、プラットフォームを判定する（判定の一覧は参照情報の窓口の一覧（第7章 2.1「初版の窓口の一覧（参照情報の初期の中身）」）と同じ。それ以外は一般のサイト）。自分の端末の一覧に同じドメイン・URL があれば知らせる|
|2|転載されている画像を、自分のブラウザで保存したファイル、または画像の URL で指定する（任意）|画像を取り込み、透かしの読み出しと PDQ を計算し、自分の作品データと照合（4）|
|3|自分のブラウザでページの画面を撮り、その画像を入れる（ログインが要るページは必須。それ以外は推奨）|画面の画像のハッシュを計算|
|4|（既定で行う）ページの記録を取る。段1の URL を入れた時点で、「登録と同時にページの記録を取ります。相手のサイトにこの PC の IP アドレスが見えます」を示し、「この登録では取らない」の選択を置く（既定は取る）|段6を押した時に、スクリプトを実行しない取得（2.2）でページの HTML と主な画像を保存する（「取らない」を選んだ場合を除く）|
|5|（任意）取っておくべき証拠の入力欄（2.3）を埋める|—|
|6|「登録する」を押す（ボタン1つ）|証拠の保全（3）、次に事件記録の作成と記録の電子署名、次に端末に保存、次に時刻証明（接続がなければ後で付ける。時刻証明の応答は事件記録に書き足さず、別の追記の記録 `status/<連番>.json` として加える。3.2）（第1章 7「実行時の場面」）|

- ボタン1つ（R-6-1-1「ボタン1つで登録できる」）：URL と段6だけで登録でき、そのとき転載ページの記録（段4）も既定で取る。設計計画書 10.2 は「登録と同時に証拠が保全されます。利用者は、何が証拠として必要であるかを知っている必要はありません」とし、10.3 は「いつ、どこで公開されていたか（②）」の記録を登録の時点で残すことを求めるため、ページの記録を利用者の操作に頼らない。段2・段3・段5 は任意の追加であり、省いた場合は証拠が少なくなる旨を表示する。
- IP アドレスの兼ね合い：取得すると相手のサイトに利用者の IP アドレスが見える（第13章 H-26「転載ページの記録を取ると（登録の既定）、相手のサイトに利用者の IP アドレスが見える」）。既定で取り、見えることを登録の前に示し、その登録に限り外せるようにする。外した登録には「ページの記録なし（②が画面の画像のみ）」の印を付ける。
- 端末の中に記録（R-6-1-3「登録は利用者の端末の中に記録され、他の利用者の記録に影響しない」）：事件記録は利用者の端末に置き、利用者の鍵で記録の電子署名を付ける。他の利用者の記録に影響しない。

### 2.2 スクリプトを実行しない取得

- HTTP GET（接続10秒、全体60秒で打ち切り、転送は5回まで、1つの応答（ページ、画像それぞれ）50MB まで。いずれも初期値。第1章 4.2「外部とのやり取り」の表と同じ）。応答の本文・ヘッダー・最終の URL・取得の時刻（UTC）・応答したサーバーの IP アドレスを保存する。
- HTML の中の `og:image`・`<img>` のうち大きいもの上位5件を同じ方法で取得する。JavaScript・CSS・フォントは取得しない。
- 取得物は画面に描画しない。画像は第3章「署名処理」と同じ画像の基盤（Rust の image crate）で読み込む（読み込めないものはハッシュのみ）。
- ログインの画面に転送された場合は、その応答をそのまま記録し、「ログインが要るため、画面の記録（段3）が必要です」と示す。
- 要求の見出し（DD-6-8「取得の要求は本システムを名乗らない」）：User-Agent と Accept-Language は、アプリの画面の部品（WebView）が持つ値を使う。Cookie と Referer は送らない（利用者のブラウザのログインの状態を持ち込まない）。
- 取得の前の知らせ（第1章 4.2「外部とのやり取り」）：相手のサイトに利用者の IP アドレスが見えることと、気になる場合は VPN を使えること（Berkeley Protocol 101段）を示す。本システムは VPN を用意しない。

### 2.2.1 WARC での保存

- 1回の取得（ページと主な画像）を1つの WARC のファイル（`capture-<連番>.warc.gz`）にまとめる。記録の種類は warcinfo（取得の道具とその版）、request（送った要求）、response（受けた応答）、metadata（取得の時刻、最終の URL、応答したサーバーの IP アドレス、TLS の証明書の主体と発行者）とする（ISO 28500 の記録の種類）。
- 部品：warc の crate（0.4.0、MIT、2024-11 更新、crates.io の累計の取得数 約237万）。WARC 1.0・1.1 の記録の読み書きを持つ。［要実測］書き出した WARC を一般の道具（pywb 等）で開けること。

### 2.2.2 画面の画像の撮り方の案内

- Berkeley Protocol（155段）は、ページ全体の画面の記録（日時の入ったもの）を、URL・HTML のソースと並ぶ最低の基準に挙げる。利用者には次を案内する。

  1. ブラウザの「ページ全体の画面の記録」の機能で撮る（Firefox は画面の記録の機能の「ページ全体を保存」、Chrome は開発者の道具の「フルサイズのスクリーンショット」）。

  2. 画面の上の URL の欄と、OS の時計が写った画面の画像も1枚撮る（ページ全体の記録には URL と日時が写らないため）。

  3. ログインが要るページは、ログインした状態で撮る。

- アプリは取り込んだ画面の画像の撮った日時を読む。ブラウザのページ全体の画面の記録は多くが PNG であり撮った日時を持たないため、その場合はファイルの更新の日時を使い、「ファイルの日時（撮った日時の記録ではない）」と区別して記録する。どちらかが登録の日時と大きく違う（24時間以上。初期値）場合は確かめを求める。日時が分からない場合は「日時なし」と記録する。

### 2.3 取っておくべき証拠の入力欄

|欄|目的|
|---|---|
|転載者のアカウント名・表示名|申立て・調査で相手を特定する|
|投稿の日時（ページに表示されたもの）|いつから公開されていたか|
|閲覧数・いいね等の数（表示されていれば）|損害の程度の資料|
|商用の利用の種類（複数選べる：有償の配布・販売、広告、商品化、AI の学習のデータ、なし・分からない）|商用の利用の優先（第7章 6.2「共同での対応と優先」、法務 L-5「肖像権・パブリシティ権（日）」）|
|同じ転載者の他の投稿の URL|継続性の資料|
|自由記述|—|

- 画面は「わかる範囲で」と案内し、空欄でも登録できる。

### 2.5 収集の記録

- 形は Berkeley Protocol の附属書 IV「オンラインのデータの収集の用紙」に倣う。

|附属書 IV の項目|本システムで記録するもの|
|---|---|
|収集者|署名者のハンドルネームと告知コード（氏名は記録しない。書き出しの時に利用者が報告書に書き足せる。3.4）|
|収集の端末の IP アドレス|記録しない（端末から外に見える IP アドレスは、外部に問い合わせないと分からないため）。利用者が報告書に書き足せる|
|収集の開始と終了の日時|登録の画面を開いた時刻と、登録を押した時刻（UTC）|
|対象の URL|入力の URL と、取得の最終の URL|
|HTML のソース|WARC の中（2.2.1）|
|画面の画像|取り込んだ画面の画像（2.2.2）|
|取得したデータ|取得した画像の一覧|
|IP アドレス|応答したサーバーの IP アドレスと DNS の結果（5）|
|収集の包みのハッシュの一覧、その一覧のハッシュ|証拠のファイルごとの SHA-256 の一覧と、一覧の SHA-256（3.2 の時刻証明の対象）|

- 加えて記録するもの：アプリの版、取得の道具の版、端末の時計のずれ。時計のずれは、時刻証明の応答の時刻と端末の時計の差として記録する（Berkeley Protocol 155段(g) は、端末の時計を時刻の同期で合わせることを求める。本システムは端末の時計を直さず、ずれを記録する）。

### 2.6 第2段からの受け口

- `source: auto` の登録は、利用者がアプリで内容を確かめて承認してから、記録の電子署名を付けて端末の事件記録に加える（自動では登録しない）。第2段の設計計画で詳細を定める。

## 3. 証拠の保全

### 3.1 後日示すべき事項との対応（設計計画書 10.3）

|番号|示すべき事項|本システムで残すもの|
|---|---|---|
|①|自らの作品であること|作品データ（原本の指紋、出力の SHA-256・PDQ、マニフェストの写し、時刻証明）を事件記録から参照|
|②|いつ、どこで公開されていたか|画面の画像、スクリプトを実行しない取得の記録（HTML、ヘッダー、最終 URL、取得時刻）、2.3 の入力、証拠一式への時刻証明|
|③|同一の画像であること|不可視透かしから読み出した識別番号、PDQ の距離（4）|
|④|誰が、どこで公開したか|DNS、IP アドレス、ASN、国、ドメインの登録情報（5）、2.3 のアカウント名|
|⑤|許可範囲の外の利用であること|照合した作品の許可範囲・同封文書のハッシュ（第5章「権利文書」）、告知の掲示（第2章「署名の情報と照合」）|

### 3.2 時刻証明

- 証拠のファイルごとの SHA-256 を並べた一覧（JSON）の SHA-256 について、RFC 3161 の時刻証明を取る（ここでの時刻証明は C2PA の検証器とは関係なく、時刻の証拠として使う）。一覧と時刻証明の応答は、状況の追記（`status/<連番>.json`）として事件に加える。
- 証拠を補強する外部の手段（設計計画書 10.3 が参照を定めるもの）：中国の互联网法院は、電子署名・可信时间戳・ハッシュ値の検証・ブロックチェーン等の技術的な手段、または電子の取証・存証の平台の認証により真実性を証明できる電子データを確認する（最高人民法院关于互联网法院审理案件若干问题的规定 第11条）。日本では、公証人が五感で体験した事実を記す事実実験公正証書が、ウェブページの表示の状態の保全に用いられる。本システムはこれらの手続を行わず、対処の案内（G-17「対処の案内」）の「さらに備えるには」に名前とリンクを示す。証拠一式の書き出し（3.4）は、これらの手続にそのまま持ち込めるファイルの形とする（法務調査 L-24「電子署名・電子データの証拠としての扱い（日・中・米）」）。
- 有料の TSA（日本の認定事業者、中国の可信时间戳）は、利用者が事件ごとに選べる。費用は利用者の負担（NRSD は仲介しない。利用者が契約した TSA のアカウントをアプリに設定する）。［要見積］各事業者の個人向けの提供と料金。

### 3.3 取得の失敗

|場面|扱い|
|---|---|
|URL が既に消えている（404・410）|その応答を記録し、画面の画像があれば登録できる|
|接続できない（遮断・タイムアウト）|失敗を記録し、画面の画像で登録。後で「今の状態を確かめる」（6）で再試行|
|ログインに転送|2.2 のとおり|
|応答が大きすぎる（50MB超）|先頭の50MBとハッシュ、打ち切りの旨を記録|

### 3.4 書き出し

- 「証拠一式を書き出す」で、事件ごとに zip を作る：事件記録と記録の電子署名、証拠のファイル（WARC、画面の画像、取得した画像）、時刻証明の応答、照合した作品データ、同封文書の写し、収集の記録（2.5）、検証の手順書（TXT、日・中・英）、報告書（TXT。登録の概要、①〜⑤の対応、ハッシュの一覧）。
- 報告書には、利用者が書き足す欄（氏名、収集の端末の IP アドレス等）を設ける。書き足した内容はアプリに保存しない（書き出しのファイルにだけ入る）。
- 検証の手順書には、ハッシュの計算方法（OS の標準コマンド）と、時刻証明の検証方法（OpenSSL のコマンド）を載せる。専門家が本システムなしで確かめられるようにする。

## 4. 照合

### 4.1 一致度の示し方

|結果|表示|
|---|---|
|不可視透かしから識別番号を読み出せ、自分の作品データに一致|「一致（透かし）：識別番号 XXXXX-XXXXX-XXX」|
|透かしは読めないが PDQ の距離が0〜15（初期値）|「ほぼ一致（見た目の指紋）」|
|PDQ の距離が16〜31|「似ている（見た目の指紋）：加工された同じ写真の可能性」（第3章 6「照合用ハッシュ」 の照合のしきい値31以下の内）|
|透かしから識別番号を読み出せたが、自分の作品データにない|「他の人の番号の透かし」。権利者を装う者の手がかりの画面（第10章 G-24「手がかりの比較」、第2章 4.4「権利者を装う者が現れた場合の手がかり」）へ案内する|
|PDQ の距離が32以上、透かしなし|「一致を確認できません」|

- 一致の判断と登録の責務は利用者が負う（D-10-6「照合の判断および登録の責務は、登録した利用者本人が負う」）。「一致を確認できません」でも登録はできるが、一覧で「一致を確認できない登録」と印を付け、申立ての前に確かめるよう示す。

### 4.2 何に抵触しているか

- 照合した作品の許可範囲と、転載の態様（2.3 の「有償の配布」、公開されていること）から、次の候補を示す：「許可範囲外の公開（転載）」「商用の利用（別途の許諾なし）」。「照合データの除去」の候補は、C2PA を残す経路（第3章 10.3「投稿先・Cloud での残存」で残ると確かめた投稿先・Cloud）で C2PA署名が無い場合、または転載画像が受け渡し用の出力から C2PA署名だけを除いたもの（形式の変換・再圧縮を伴わず、画素が同じ）である場合に限って示す。SNS の多くは投稿の時に C2PA を消すため、SNS で C2PA署名が無いことは除去の手がかりにならない（日本法でも技術的な制約による除去は除かれる。法務調査 L-1「権利管理情報の除去・改変（日）」）。
- 候補は法的な判断ではなく、許可範囲との照らし合わせの結果として示す（第7章 7「線引き」）。

## 5. 誰が、どこで（④）

- DNS で A・AAAA を引き、IP アドレスについて RIR の RDAP で ASN・組織・国・不正利用の窓口を取る。ドメインについてドメインの RDAP（ICANN Lookup と同じ仕組み）で登録事業者・窓口を取る（企画草案［23］）。
- 中国のサイト：ICP 備案号をページの末尾から読み取れた場合は記録する。工業和信息化部の備案の照会（企画草案［22］）は利用者が行う手順として第7章「法的対応ガイダンス」で案内する（照会の画面に画像の確認があるため、アプリから自動で引かない）。
- CDN の裏側の本当のサーバーは RDAP では分からないことがある。その場合も CDN 事業者の不正利用の窓口が申立て先になる（第7章「法的対応ガイダンス」）。

## 6. 状況確認

### 6.1 状況の記録

|状況|記録する者|
|---|---|
|登録済み|アプリ（登録時）|
|申立て済み（日時、窓口、方法、申し出た者の立場（第7章 3.4「申し出る者の立場」））|利用者の入力（第7章の流れから）|
|事業者の応答（受付、判断の結果）|利用者の入力|
|削除を確認|利用者の操作（6.2）|
|再掲載を確認|利用者の操作|
|取り下げ|利用者の入力（7）|

- 申立ての後の手続の期限（日本の大規模特定電気通信役務提供者の7日の通知、米国の反論の後の10〜14営業日等）は、第7章 6.3「手続の期限の表示」の表により事件の画面に示す。

### 6.2 今の状態の確かめ

- 利用者がボタンを押したときだけ、登録した URL に対してスクリプトを実行しない取得を1回行い、HTTP の状態・本文のハッシュ・画像の有無を記録し、時刻証明を付ける。
- 定期の自動確認はしない。一覧の画面で「最後に確かめた日」を示し、利用者が思い出せるようにする。

## 7. 訂正

- 誤登録の取り下げ：利用者が理由を選び（誤り、許諾済みだった、その他）、取り下げの記録を追記する。証拠のファイルは削除し、事件記録には取り下げと理由と日時を残す（第1章 8.4「保持と削除」）。一覧の件数から除く。
- 自分の作品でない転載を登録した場合（R-6-6-2「自分の作品でない転載を登録した場合の扱いが決まっている」）：登録は端末の中にとどまり、他の利用者や事業者には届かない。害が生じるのは、利用者がその登録をもとに申立てを送った場合であり、申立ての前に照合の結果と手がかり（第2章 4.4「権利者を装う者が現れた場合の手がかり」）を示し、責務が利用者にあること（D-10-6「照合の判断および登録の責務は、登録した利用者本人が負う」）を示す。

## 8. 一覧と手段

- 一覧：登録した転載を、転載サイト（ドメイン）ごとに束ね、件数、最初の登録日、最後に確かめた日、状況（6.1）、商業的な利用の印（第7章 6.2「共同での対応と優先」）を示す。
- 手段の選択肢：各事件について、とり得る手段（投稿先の窓口への申立て、CDN・ホスティング事業者への知らせ、中国のサイトの ICP 備案の照会、専門家への相談の準備としての書き出し）を示す。どれを講じるかは利用者が判断する（第7章「法的対応ガイダンス」）。
- 共有：他の利用者と共有しない（D-10-9「登録した転載の情報は利用者の端末に一覧としてまとめ、とり得る手段の選択肢を示す。利用者の間の共有は行わない（第2段で扱う）」）。転載サイトの情報の共有と、著作者以外の者から著作者への通知は、第2段の設計計画で扱う（D-13-3「著作者への通知のための連絡先の登録は、第2段の設計計画で扱う」）。

## 10. 本章で宣言する破れ

- 証拠は利用者の端末にのみあり、書き出しをしていない利用者が端末を失うと証拠を失う（第8章「リポジトリとデータ管理」）。
- ログインが要るページは、利用者の画面の画像にしか頼れない。画面の画像は加工し得るため、証拠としての力は取得の記録より弱い。
- CDN の裏側のサーバーは特定できないことがある。調べても所在が分からない転載には対処しない（D-9-7「サーバーの所在は調査により判明するものとし、判明しない場合は断念する」）。
- 転載ページの画面の記録に写り込む第三者の著作物の扱いは、中国では明文の例外を確認できず、専門家の確認を要する（法務 L-21「証拠のための複製（日・中・米）」）。
- 状況確認は利用者の操作のみのため、利用者が確かめない間の変化（削除・再掲載）は記録されない。
- 照合の結果は確率にとどまる。再圧縮・切り抜きの後は一致度でしか示せない（第13章 H-2「照合の結果は確率にとどまる」）。
- 転載サイトの情報を利用者の間で共有しないため、他の権利者が同じ転載サイトに気付きにくい（第13章 H-24「転載サイトの情報を利用者の間で共有しない」）。
