## 1. 设计决定的一览

|编号|决定|理由|被否定的方案|

## 2. 许可范围

### 2.1 选项（O-04“许可范围的选项”的决定）

基本范围（选择1个）

|ID|名称|内容|
|---|---|---|
|P1|仅限欣赏|购买者本人作为个人观看图片。复制限于保存到购买者本人的终端|
|P2|欣赏与私人打印|在P1的基础上，购买者本人为个人欣赏而打印|

追加许可（任意附加）

|ID|名称|内容|
|---|---|---|
|A1|在社交平台上介绍|购买者在自己的社交平台上，标明权利人的名字与识别编号，介绍缩小后的图片（长边1080像素以下。初始值）。不包括有偿的分发、销售|
|A2|个人加工|购买者本人为个人欣赏进行的加工（裁切、颜色的调整等）。不包括公开加工后的图片（选择A1时可在A1的范围内公开）|
|A3|AI学习、推理的许可|允许用于AI的学习、推理、数据挖掘（默认为不可。反映在cawg.training-mining的4个项目中。第3章 3.1“记录的项目”）|

始终包含的条件

- 商业利用（广告、商品化、有偿的分发、销售）需要另行取得权利人的书面许可。
- 不可向他人转让、共享、转载（A1的范围除外）。
- 权利（著作权、肖像权）不因购买而转移。
- 不得删除比对数据（C2PA签名、隐形水印、识别编号）。
- 社交平台用图片默认的许可范围为“相当于P1：仅限浏览，禁止转载”（第3章 8.2“系统的差异”）。
- 简短标记（可见签名的插入字段`{license}`。第4章 3.1“内容与插入字段”）：把基本范围与追加许可的ID以`+`连接（例：`P1`、`P2+A1+A2`。与Creative Commons的缩写（CC BY-NC）相同的思路）。

### 2.2 面向非技术人员的说明

- 每个选项附上一句说明，以及带插图的“可以做的事／不可以做的事”示例（在第10章“界面与设计”中做成界面）。
- 判定的标准：在使用者试用中，阅读说明的使用者中8成以上能正确回答在所选范围内购买者是否可以发到社交平台（第10章“界面与设计”）。

### 2.3 与图片的关联

- 以销售的输出（交付用）为单位选择1个许可范围，记录到该文件夹所有图片的作品数据（rights）与清单（jp.nrsd.rights、cawg.metadata的使用条件、cawg.training-mining）中（第3章“签名处理”）。
- 登记（第6章“登记与证据保全”）时，以从转载图片的隐形水印读出的识别编号查找作品数据，与所选的许可范围对照，显示“违反了什么”（D-9-2“以销售时选择的许可范围，作为判断转载抵触了什么的基准”）。
- 候选的规则（第6章 4.2“违反了什么”所显示的候选）：根据转载的形态（有偿的分发、已公开。第6章 2.3）与许可范围，显示“许可范围外的公开（转载）”“商业利用（无另行许可）”。“比对数据的删除”只在保留C2PA的途径（第3章 10.3“在发布网站、云端的保留”中确认会保留的发布网站、云端）上没有C2PA签名时，或转载图片是从交付用输出中仅去掉C2PA签名者（不伴随格式转换、再压缩，像素相同）时显示。多数社交平台在发布时会去掉C2PA，因此社交平台上没有C2PA签名不构成删除的线索（日本法也把技术限制导致的删除除外。法务调查 L-1“权利管理信息的去除、改变（日）”）。

### 2.4 销售后的变更

- 不改变已分发图片的许可范围（因为已分发图片的清单与随附文件会成为证据）。
- 想扩大范围时，由权利人向购买者另行给予许可（在本系统之外）。本系统不显示许可文字的示例。因为许可的条件（对价、范围、期间）按每笔交易决定，无法以范本表示（DD-5-1“许可范围由基本范围与附加许可选择”）。
- 不缩小范围（因为这会单方面撤销购买者已经获得的许可）。
- 参考信息发布带“订正”标记（错误的窗口、文字的订正。第8章 3.4目录的`corrections`：订正的文件、含错误的最初版本、理由）的版本时，应用自动列出受影响的过去作品（以含错误的版本到订正前的版本导出、使用了该文字文件者），并在输出文件夹生成订正版随附文件（`00_RIGHTS_ERRATA.txt`。原文件与订正的差异、原哈希与订正版的哈希）。使用者只需重新放到给购买者的位置。许可范围不变（2026-09-30 NRSD的要求）。输出文件夹不存在时让使用者选择位置（默认为原位置的上级），并将新位置追记到作品数据的输出位置（第3章 7.2）。

## 3. 随附文件

### 3.1 构成

|文件|内容|语言|
|---|---|---|
|`00_RIGHTS_README.txt`|共通部分（3.2）|日、中、英并列在1个文件中|
|`00_RIGHTS_<国家代码>.txt`|国别部分（3.3）|该国的主要语言与英语|
|`00_RIGHTS.json`|机器可读的许可范围（ODRL 2.2。3.6）|—|

- 格式为TXT（UTF-8，无BOM，换行CRLF）。在任何操作系统上都能打开，在云端的预览中也能阅读（D-9-5“将涵盖所有国家的信息作为链接目标公开，仅对购买者中常见的国籍附上文本文稿”的“TXT”）。
- 放在文件夹的最上层，名称以`00_`开头，使其排在图片之前。
- 3个文件起到与Creative Commons许可的3层（法律文本、人可读的Deed、机器可读的ccREL）相同的作用：国别部分为法律文本，`00_RIGHTS_README.txt`为人可读的摘要，`00_RIGHTS.json`（ODRL）为机器可读的形式。公开页面的“核验”页把ODRL以与CC的Deed相同的形式（可以、条件、不可以的3列与标记）展开为人的语言显示（第8章 3.3）（2026-10-01 NRSD的要求）。

### 3.2 共通部分的骨架

- 设计计划书 9.2“随附文件”的5个事项（①关于权利的条款（包括权利不转移的意旨）、②许可范围、③不得擅自授受的一句、④比对数据被删除并在范围外使用时权利人采取的手段、⑤何种行为可能被追究何种责任），与各行的对应如下。

|顺序|项目|骨架|计划书9.2的事项|
|---|---|---|---|
|1|本图片的权利人|网名、声明所在账号|在①中追加的内容（显示权利人）|
|2|不擅自与他人授受（DD-5-3“禁止擅自授受的一句放在共同部分”）|“未经权利人许可，请勿将本图片转交、共享、转载给他人”|③|
|3|权利不转移|著作权、肖像权不因购买而转移给购买者|①|
|4|许可范围|所选P、A的说明|②|
|5|关于比对数据|图片中含有C2PA签名、隐形水印与识别编号（编号的一览见`00_RIGHTS.json`），故意删除在部分国家可能违法（参照国别部分）|④的前提|
|6|在范围外使用时权利人可能采取的手段|删除申诉、损害赔偿的请求等（参照国别部分）|④|
|7|做什么可能被追究什么|参照国别部分。全面覆盖见公开页面的链接|⑤|
|8|咨询处|权利人的声明所在账号|追加的内容|
|9|许可的性质|许可是给购买者本人的非独占许可，不可转让给他人，不可再许可给他人。不规定期间（只要持有图片）。不限地域|①|
|10|在范围外使用时|许可限于范围内的使用，范围外的使用本来就不被允许。权利人有时会撤销许可|①|

- 表述为事实的记载，不采用强硬的合同措辞（设计计划书 9.2“随附文件”：对担心卖不出去的顾虑）。
- 9的许可性质，与销售场所的规约给予会员的许可性质（Patreon的规约：非独占、不可转让、不可再许可、可撤销的、用于私人与非商业观看的有限许可。法务调查 L-17“销售平台的条款”）保持一致，不相抵触。给予比销售场所的规约更宽的许可时（A1、A2），明示为权利人所选。

### 3.3 国别部分的骨架

|项目|日本的示例（法务的出处）|
|---|---|
|权利管理信息的删除|著作权法第113条第8款（视为侵权。伴随方式转换的技术限制所导致的删除除外）、第120条之2第5项（以营利为目的的罚则。告诉乃论）（L-1“权利管理信息的去除、改变（日）”）|
|擅自公开|公众传输权（著作权法第23条）、复制权（第21条）的侵害与救济（停止侵害、损害赔偿、刑罚）（L-32“著作权的侵害与救济（日、中、美）”），损害赔偿的请求期间（L-20“损害赔偿请求的期间（日、中、美）”）|
|肖像|肖像权（不被随意拍摄、公开的人格利益。社会生活上忍受限度的标准）与形象权（L-5“肖像权、形象权（日）”）|
|删除申诉|《信息流通平台应对法》（L-7“删除申请的程序（日）”）|

- 中国（L-2“权利管理信息的去除、改变（中）”、L-6“肖像权（中）”、L-8“删除申请的程序（中）”）、美国（L-3“权利管理信息的去除、改变（美）”、L-9“删除申请的程序（美）”）也以相同的骨架制作。其他国家以“全面覆盖的链接”显示。
- 在国别部分的各项目中，载明法务文件的出处（L编号的原出处URL）。

### 3.4 改写的检测

- DD-5-4“随附文件的SHA-256记录在清单中”。把图片与随附文件的文件夹放入应用的“核验”界面（第10章 G-13“核验”）后（只放入文件夹时使用其中的图片，一张图片都没有时显示“没有图片”），把各文件的SHA-256与清单的一览比较，显示一致、不一致、一览中没有的文件、缺少的文件。图片本身的核验依据第3章 10.2“使用者的确认”。
- 在公开页面的“核验”页（第8章 3.3）上，拖入图片与随附文件的文件夹也能进行同样的比对（一致、不一致、没有、多余）。只在浏览器中运行，不发送到任何地方。购买者、专家无需应用即可核验（2026-10-01 NRSD的要求）。
- 订正版（2.4）的辨别：在`00_RIGHTS_ERRATA.txt`的开头写入订正对象的各原文件的SHA-256与订正版的SHA-256，并把记录电子签名（JWS detached、`x5c`。第1章 8.3）附为`00_RIGHTS_ERRATA.txt.sig`。G-13与公开页面的核验，对清单一览中没有的`00_RIGHTS_ERRATA*`，若签名链的个人根证书与图片`x5chain`的根证书一致且所写的原哈希与一览相符，则显示“正当的订正版”（以发行者事后的签名文补充。与CRL同一思路）。

### 3.5 法律上的定位（在法务中处理）

- 随附文件是在Patreon等销售场所的规约之上显示“创作者许可”内容的文件（法务 L-17“销售平台的条款”）。是否作为独立的合同成立因国家而异，需要专家的确认（I-08“权利文书的措辞”）。本系统把随附文件作为“事实与许可范围的标示”处理，不保证合同的成立。

### 3.6 机器可读的许可范围（ODRL）

- 格式：ODRL 2.2的JSON-LD（上下文为`http://www.w3.org/ns/odrl.jsonld`）。策略的种类为Offer（权利人提出的条件。不特定购买者）。
- 对应：

|许可范围|在ODRL中的表示|
|---|---|
|P1 仅限欣赏|许可：`display`、`reproduce`（约束：限于保存到购买者本人的终端）|
|P2 欣赏与私人打印|在P1的基础上，许可：`print`（约束：私人的使用）|
|A1 在社交平台上介绍|许可：`distribute`（约束：长边1080像素以下，非有偿）。义务：`attribute`（显示权利人的名字与识别编号）|
|A2 个人加工|许可：`modify`（约束：私人的使用）|
|A3 AI学习、推理的许可|许可：本系统的扩展操作`nrsd:aiTraining`、`nrsd:aiInference`、`nrsd:dataMining`|
|始终包含的条件|禁止：本系统的扩展操作`nrsd:commercialUse`（商业）、`distribute`（A1的范围除外）、比对数据的删除（`nrsd:removeProvenance`）。若不选择A3，则禁止AI的3个操作|

- 本系统扩展操作的名称空间为`https://c2pa4cosplayer.nrsd.jp/ns/odrl/`（前缀`nrsd:`），在公开页面上刊载操作的定义。标识符不用未注册的`urn:nrsd:`而以HTTPS的URI书写（W3C的“Cool URIs”、ODRL示例的惯例）：策略为`https://c2pa4cosplayer.nrsd.jp/id/policy/<批量处理的编号>`，权利人为`.../id/notice/<声明码>`，对象为`.../id/work/<识别编号>`。
- 对象（Asset）为识别编号的一览，提出者（assigner）为签名者（权利人）的网名与声明码的1人。经授权者输出的主要权利人，以及有共同权利书面文件的输出的共同权利人，以本系统的扩展项目`nrsd:grantor`、`nrsd:coRightsHolder`（ODRL的Party。网名与声明码）表示。在`00_RIGHTS_README.txt`的“权利人”行（3.2的1）中也并列同样的人。
- 示例（选择P1与A1时的骨架）：

```
{
  "@context": "http://www.w3.org/ns/odrl.jsonld",
  "@type": "Offer",
  "uid": "https://c2pa4cosplayer.nrsd.jp/id/policy/{批量处理的编号}",
  "assigner": {"uid": "https://c2pa4cosplayer.nrsd.jp/id/notice/{声明码}", "name": "{网名}"},
  "target": ["https://c2pa4cosplayer.nrsd.jp/id/work/{识别编号}", "..."],
  "permission": [
    {"action": "display"},
    {"action": "reproduce", "constraint": [{"leftOperand": "purpose", "operator": "eq", "rightOperand": "nrsd:personalDeviceStorage"}]},
    {"action": "distribute",
     "constraint": [{"leftOperand": "nrsd:longEdgePixels", "operator": "lteq", "rightOperand": 1080},
                    {"leftOperand": "payAmount", "operator": "eq", "rightOperand": 0}],
     "duty": [{"action": "attribute"}]}
  ],
  "prohibition": [
    {"action": "nrsd:commercialUse"}, {"action": "nrsd:removeProvenance"},
    {"action": "nrsd:aiTraining"}, {"action": "nrsd:aiInference"}, {"action": "nrsd:dataMining"}
  ]
}
```

- `purpose`、`payAmount`是ODRL共通词表中的左操作数（约束的对象）。`nrsd:`的名称是本系统的扩展，在公开页面上定义。［需确认］在实现之前，以ODRL的验证工具确认形式的正确性。
- ODRL标准操作的定义：display为“临时的显示”，print为“有形且永久的显示”，reproduce为“复制”，distribute为“向第三方提供”，modify为“内容的变更（不产生新的对象）”，attribute为“使用时的标示”（W3C的ODRL共通词表）。

## 5. 国家

- 随附的国家：购买者中常见国籍的份，由使用者在“权利文书的对象国”（第1章 10.8“语言与国家”）中选择（可多选。设计计划书 9.3“针对的国家”）。购买者中常见的国籍由使用者自己掌握（设计计划书 9.3“针对的国家”）。应用不设默认的国家，不持有购买者的信息（销售管理在范围外）。不选择国家时，只随附共通部分与全面覆盖的链接。
- 无法缩小购买者的国家范围（I-07“购买者国家的掌握”的结论）。销售场所的注册信息与连接来源的国家，在经由VPN时失去意义，无法确定购买者的国籍。图片会跨越国界传递。因此本系统采用不依赖购买者国家的做法：共通部分以所有语言随附，全面覆盖的信息以公开页面的链接显示，国别部分由使用者自行判断选择（也可以不选）。
- 全面覆盖的链接目标：公开仓库的公开页面`/rights/`（各国法律的要旨与出处的一览。由参考信息生成）。
- 准据法的思路（在法务中处理。O-03“准据法的思路”）：参考设计计划书 9.5“准据法的思路（参考）”的两层（许可范围为合同的问题，侵权为被请求保护国法律的问题），放置在随附文件中载明“许可范围的解释依据销售者（权利人）所在国的法律”这一意旨的方案。采用与否取决于专家的确认（I-06“各国权利的差异”、I-08“权利文书的措辞”）。在确认之前不写入随附文件，也不设销售者国家的输入（O-03“准据法的思路”处于放置方案的阶段）。
